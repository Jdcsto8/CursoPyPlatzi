Python está en todas partes: Instagram maneja millones de usuarios, la NASA analiza datos de ciencias espaciales y Spotify recomienda tu siguiente canción. ¿Por qué Python está en todas partes?

Python funciona en ciencia, redes sociales y entretenimiento. Esa versatilidad se apoya en su sintaxis parecida al inglés y en una curva de aprendizaje amable. Permite concentrarse en la lógica y en resolver problemas, en lugar de perder tiempo con reglas complejas.

¿Qué lo hace simple y poderoso?

Es un lenguaje de alto nivel. Permite pensar en soluciones, no en detalles de bajo nivel.
Su sintaxis es intuitiva y clara. Ahorra horas de aprendizaje de reglas.
Favorece empezar rápido: de un "hola, mundo" a proyectos reales.
¿Qué se puede crear con Python?

Análisis de datos genómicos.
Predicción del clima.
Entrenamiento de redes neuronales.
Esa amplitud explica por qué tantas personas que recién arrancan y también empresas enormes lo eligen. Python es conocido como el lenguaje de la ciencia por su impacto en datos y modelos.

¿Qué aprenderás paso a paso?

Vas a cubrir fundamentos clave para construir desde cero y automatizar tareas. Todo orientado a pensar con lógica y tomar decisiones en tu código.

Variables para manejar información.
Booleanos para expresar verdadero o falso.
Decisiones con if y else para controlar el flujo.
Automatizaciones con bucles para repetir acciones.

Add to PATH: agrega VS Code a las variables de entorno para que esté disponible desde cualquier terminal.

Al abrir el instalador, antes de presionar Install Now, activa estos dos checkboxes:

Add Python to PATH: agrega python.exe a las variables de entorno de Windows, para que Python esté disponible en todas las terminales.
Privilegios de administrador para py.exe: el ejecutador de Python correrá con permisos elevados cuando lo necesites.

# 3 Variables de entorno de Python en Windows

Configurar las variables de entorno de Python en Windows es el paso que te permite ejecutar Python desde cualquier carpeta o terminal del sistema. Si marcaste la casilla Add to Path durante la instalación, ya tienes medio camino recorrido; lo que sigue es entender qué hace esa configuración y cómo revisarla.

¿Qué son las variables de entorno y por qué importan en Python?

Las variables de entorno son rutas que el sistema operativo guarda para saber dónde buscar programas cuando los llamas desde la terminal. Cuando instalas Python con la opción Add to Path activada, el instalador agrega automáticamente las carpetas necesarias para que escribir python en cualquier PowerShell o consola funcione sin errores.

¿Qué hace la opción Add to Path al instalar Python? Agrega las carpetas de Python a la variable Path del sistema, lo que permite ejecutar Python desde cualquier directorio sin escribir la ruta completa.

Sin esta configuración tendrías que navegar hasta la carpeta exacta donde vive el ejecutable cada vez que quisieras correr un script. Y eso, en la práctica, es un dolor de cabeza.

¿Cómo abrir las variables de entorno en Windows paso a paso?

El acceso es directo desde el menú Inicio y funciona igual en español o inglés, solo cambia el nombre del resultado.

Abre el menú Inicio y escribe la palabra variable.
Selecciona la primera opción que aparezca: Variables de entorno o, si tu sistema está en inglés, Edit the system environment variables.
En la ventana que se abre, haz clic en el botón que permite editar las variables de entorno.
Al entrar verás dos secciones bien diferenciadas, y conviene saber qué hace cada una antes de tocar nada.

¿Cuál es la diferencia entre variables de usuario y variables del sistema?

La ventana de configuración divide las variables en dos bloques con alcances distintos:

Variables de usuario: están en el sector de arriba y aplican únicamente al usuario actual de la computadora.
Variables del sistema: están en el sector de abajo y aplican a todos los usuarios que usen ese equipo.
La instalación de Python suele agregar sus rutas a la variable llamada Path, que es la que el sistema consulta para localizar ejecutables.

¿Dónde queda registrado Python en las variables de entorno? En la variable Path, donde se agregan las carpetas del intérprete y de los scripts de Python para que estén disponibles en cualquier terminal.

¿Cómo verificar que Python quedó bien configurado en el Path?

Una vez dentro de la ventana de variables, haz doble clic sobre la línea que dice Path. Vas a ver un listado largo de rutas, y entre ellas deberían aparecer dos líneas relacionadas con Python: una apunta al intérprete y otra a la carpeta de scripts.

Esa es la señal de que la instalación quedó bien. Para confirmarlo en la práctica, abre una PowerShell o terminal nueva y escribe:

powershell python

Si el comando responde abriendo el intérprete interactivo de Python, la configuración está lista. Si en cambio aparece un error tipo command not found, significa que la ruta no está agregada al Path y deberás añadirla manualmente desde esta misma ventana.

¿Por qué Python funciona en cualquier carpeta después de configurar el Path?

Porque al estar registrado en las variables de entorno, el sistema ya no necesita que le indiques dónde está el ejecutable. Lo busca automáticamente en cada una de las rutas listadas en Path, sin importar desde qué directorio abras la terminal.

Eso convierte a Python en una herramienta accesible desde cualquier punto del sistema, lo que facilita ejecutar scripts, instalar paquetes con pip y trabajar en proyectos ubicados en carpetas distintas.

Cuéntame en los comentarios si te apareció Python en el Path al revisar tus variables de entorno o si tuviste que agregarlo manualmente.

¿qué ocurre si rompes la indentación?

Si eliminas la tabulación del bloque, el editor subraya en rojo.
Al ejecutar, obtendrás un error de sintaxis por indentación en la línea del bloque.
Código con indentación incorrecta:

if 5 > 3: print("cinco es mayor que tres")

Si agregas más de una tabulación, el código puede correr, pero no sigue el estándar del equipo y causa confusión. Lo recomendable es una tabulación por nivel de bloque.
¿cómo indentar if anidados y varias instrucciones?

Un if dentro de otro if requiere un nivel adicional de tabulación.
Ejemplo con bloque interno y una instrucción al mismo nivel del bloque externo:
if 5 > 3:     if 5 > 3:         print("Cinco es mayor que tres")  # if interno     print("Cuatro es mayor que tres")      # if externo

Regla práctica: cada nuevo bloque aumenta una tabulación. Mantén la alineación para que cualquiera pueda leer tu código.

# 6 Comentarios en Python: una y multilínea


Comentar código en Python es una de las primeras habilidades que necesitas dominar para escribir programas legibles, colaborativos y fáciles de mantener. Aquí aprenderás cómo usar comentarios de una línea, multilínea y cómo desactivar instrucciones temporalmente, todo con ejemplos directos del intérprete de Python.

Para qué sirven los comentarios en Python

Los comentarios cumplen tres funciones que vas a usar todo el tiempo cuando programes. No son decoración: son parte del flujo de trabajo real.

Hacer tu código más fácil de leer para ti y para tu equipo.
Desactivar líneas que no quieres ejecutar en un momento puntual.
Explicar qué hace una instrucción específica para quien lea el archivo después.
Cuando escribes una línea suelta como Esta es una línea de código, Python la marca en amarillo y rojo porque interpreta que está mal escrita. Apenas le agregas el símbolo correcto al inicio, la línea se pone verde y desaparece el error.

¿Qué es un comentario en Python? Es una línea de texto que el intérprete ignora durante la ejecución. Sirve para documentar, explicar o desactivar código sin borrarlo.

Cómo hacer un comentario de una sola línea

La forma más común usa el numeral, también llamado hashtag, al inicio de la línea. Todo lo que escribas después de ese símbolo queda fuera de la ejecución.

Si creas un archivo con extensión .py y dentro pones una línea comentada seguida de un print("Hola Mundo"), al ejecutar con Run Python File la terminal solo mostrará Hola Mundo. La línea comentada no tiene ningún impacto.

También puedes comentar después de una instrucción, en la misma línea. Es un patrón muy popular para explicar qué hace ese fragmento:

python print("Hola Mundo") # imprime Hola Mundo en la terminal

Python ejecuta el print con normalidad y omite todo lo que viene después del numeral.

Cómo escribir un comentario multilínea

Cuando necesitas explicar algo más extenso, tienes dos caminos. Y los dos funcionan bien según el estilo que prefieras.

Numeral en cada línea

Pones un numeral al inicio de cada renglón. Es la forma más explícita y la que muchos equipos prefieren porque deja claro que cada línea es un comentario independiente.

python

Este es un comentario

que ocupa varias líneas

y Python lo ignora completo

Comillas triples

La otra opción son las comillas triples al inicio y al final del bloque. Todo lo que pongas en medio queda fuera de la ejecución.

python """ Este será un comentario multilínea que puede tener el largo que quieras """ print("Hola Mundo")

Al guardar y ejecutar, la terminal solo muestra Hola Mundo. El bloque entre comillas triples queda ignorado.

¿Cuál es la diferencia entre usar numeral y comillas triples? El numeral es un comentario puro y se usa línea por línea. Las comillas triples son técnicamente un string que Python no asigna a nada, por eso funcionan como comentario en bloque.

Cómo desactivar una instrucción de Python con comentarios

Esta es probablemente la razón más práctica para usar comentarios en el día a día. Imagina que tienes esta instrucción:

python print("Esta línea deseo ignorarla")

Al ejecutar, aparece en la terminal junto con el resto del programa. Pero si le agregas un numeral al inicio, Python la salta sin borrarla del archivo:

python

print("Esta línea deseo ignorarla")

¿Por qué querrías ignorar una instrucción si estás trabajando en Python? Hay dos escenarios típicos: cuando esa línea genera un error y necesitas aislarla para depurar, o cuando estás probando partes específicas del código y quieres desactivar otras temporalmente sin perder lo escrito.

Es una técnica que vas a usar constantemente cuando empieces a construir programas más grandes.

Cuándo conviene comentar y cuándo no

Comentar de más también ensucia el código. La idea no es narrar cada línea, sino aclarar lo que no se entiende a simple vista.

Comenta cuando una instrucción tiene una intención que no es obvia.
Comenta cuando desactivas código temporalmente para pruebas o debugging.
Comenta para dejar contexto a quien revise el archivo después de ti.
Evita comentar lo que ya dice el propio código de forma evidente.
Una buena práctica es escribir el comentario pensando en tu yo del futuro o en alguien que abre el archivo por primera vez. Si esa persona entiende rápido, el comentario cumplió su trabajo.
